# Приложение для обработки загружаемых документов
## Цель проекта
Разработка приложения для обработки загружаемых документов

### Установка, настройка и запуск
Все необходимые зависимости указаны в файле [pyproject.toml](pyproject.toml)
Для локального запуска необходимо выполнить команды 'docker compose build' и 'docker compose up', в результате чего будут собраны необходимые контейнеры, собраны статические файлы, запустится локальный сервер, redis и celery.

### Использование функций и примеры работы
1. Регистрация и авторизация пользователей производится по модели User, содержащей поле email (логин).
При регистрации используется сериализатор UserRegisterSerializer с выводом полей pk, email, password.
2. Зарегистрированный пользователь имеет возможность загружать документы. Модель Document содержит поля:
- title - "Наименование документа" (строка)
- owner - "Пользователь" (присваивается автоматически по авторизированному пользователю)
- file - "Файл"
- status - "Статус документа" (выбор значений "Загружен" (по умолчанию), "Подтвержден", "Отклонен")
- uploaded_at - "Дата и время загрузки" (автоматическое присвоение при создании)
- updated_at - "Дата и время обновления"

При загрузке документа осуществляется его привязка к текущему пользователю в качестве владельца.
При загрузке документа создается отложенная задача send_admin_notification ([tasks.py](docs_manager/tasks.py)) для рассылки уведомления о новом документе всем активным администраторам, кроме суперюзера.
При отправке уведомления администратору к письму прикрепляется загруженный файл.
В административной панели в списке Документов реализованы быстрые действия для подтверждения и отклонения загруженных документов.
После подтверждения или отклонения документа администратором создается отложенная задача send_status_notification ([tasks.py](docs_manager/tasks.py)) для отправки уведомления пользователю, загрузившему документ, об изменении статуса документа.
Для документа имеется единственный сериализатор DocumentSerializer с выводом всех полей модели.

3. Пагинация. Для вывода списка документов используется пагинация CustomPagination с выводом по 5 объектов на страницу.

4. Безопасность. Для проекта настроен CORS. 

5. Документация. Для реализации экранов силами фронтенд-разработчиков настроен вывод документации. 

6. Работа с GitHub. При каждом push или pull_request выполняется пайплайн, описанный в [ci.yml](.github/workflows/ci.yml), который содержит следующие работы, выполняющиеся последовательно:
- запуск линтера flake8;
- запуск тестов (на sqlite).
